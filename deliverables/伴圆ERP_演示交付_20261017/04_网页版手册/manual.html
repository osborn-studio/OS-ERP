一、通用操作

1.1 登录与行业选择

步骤操作说明
1打开 http://<主机>:3001/login全站唯一的登录页（旧地址 /enter.html 会自动跳过来）
2选「美妆连锁版」或「连锁餐饮版」服装版开发中，当前不展示
3点一张角色卡片自动填入该角色的账号密码；也可以在下面手填
4点「登 录」默认进「经营看板」；门店店长账号直达 POS 收银台

为什么只有一个登录页：以前 /enter.html 是"选行业后用 admin 自动登录"，与 /login 并存 —— 结果是不管谁点入口页都是 admin 进去，客户根本看不到"不同角色菜单不同"。 现在登录只发生在一处，enter.html 只保留跳转（旧链接不失效）。

角色卡片上写了"能看到什么"，但那只是人话范围；真实菜单以登录后侧栏为准

（侧栏由 Layout.tsx 的角色族决定，卡片写细了必然与代码分叉）。

行业决定的是数据库：三个行业各有独立 SQLite 库，切换行业 = 重新登录换令牌，不是切换视图。

1.2 界面结构

区域内容
左侧栏业务菜单（按角色收敛）+ 品牌区 + 折叠按钮
顶栏当前页标题、行业版本、用户菜单（修改密码 / 退出）
主区页面内容
右下轻提示（操作结果）

1.3 列表页的通用能力

绝大多数列表页是同一个骨架（DataPage），操作方式一致：

  • 搜索：顶部关键词框，回车生效；
  • 筛选：状态下拉 / 日期范围 / 下拉字典；
  • 分页：底部页码，可改每页条数；
  • 新增 / 编辑：右上角按钮，表单按字段定义生成；
  • 删除：行内操作（是否可删由后端判断，被引用的单据会拒绝）；
  • 导出：导出当前筛选结果为 Excel。

1.4 角色与菜单的关系

  • 菜单由角色的「职责族」决定（管理员看全部）；
  • 接口由权限点决定（137 个权限点）；
  • 菜单里没有 ≠ 一定调不通，但接口会拒；反过来菜单有而接口拒，说明权限点没配。

角色默认可见范围（演示库）：

角色大体可见
admin全部
boss全部只读 + 关键审批（无系统设置）
scm 供应链主管采购 / 存货 / 计划生产 / 质量 / 委外；销售与财务只读
purchase 采购采购 / 主数据 / 存货查询 / 质量
sales 销售销售 / 订货中心 / OMS / 营销 / 经销商 / 主数据
warehouse 仓管存货 / 采购收货 / 质量 / 生产
finance 财务财务应收 / 采购应付 / 销售发票 / 报表
store 店长本店 POS / 门店库存 / 要货 / 盘点
dealer 经销商订货中心 / 对账
viewer 访客看板 + 只读查询

管理员可在「系统管理 → 角色与权限」里调整功能权限，并实时预览该角色能看到哪些菜单。

1.5 修改密码

右上角用户菜单 → 修改密码 → 输入原密码与新密码。密码用 bcrypt 存储，改完立即生效（旧令牌仍有效直到过期）。

三、AI 数据承接台

入口：左侧「AI 数据承接台」/ai

回答什么问题：能不能用一句话问出数据？

怎么用

  1. 在输入框里用自然语言提问，例如「上个月卖得最好的 5 个商品」；
  2. 系统把问题转成结构化查询，执行后返回表格 + 一句话结论；
  3. 每次提问都会写入「AI 查询日志」（系统管理 → AI 查询日志）。

注意

  • 它走的是受权限约束的取数：当前账号看不到的数据，问也问不出来；
  • 演示环境不接外部大模型时，内置的是规则式解析；接大模型后语义能力更强，但取数口径不变。

四、订货中心

入口：左侧「订货中心」/order-center

回答什么问题：门店和经销商怎么向总部订货？总部怎么确认并发货？

页面内容

区块作用
客户身份门店 / 经销商，决定价格组与可用商品
商品与价格按价格组带出协议价 / 会员价
购物车加购、改数量、看可用库存
提交订货生成订货单（进入销售订单体系）
我的订货单查看状态：待确认 / 已确认 / 已发货 / 已完成
对账单经销商看自己期间的应收与回款

典型操作（经销商下单）

  1. 用 dealer01 登录 → 订货中心；
  2. 选商品、填数量（会校验可用量）；
  3. 提交 → 生成订货单；
  4. 总部（销售/管理员）在「销售管理 → 销售订单」确认 → 占用库存；
  5. 仓库发货 → 生成发货单；
  6. 经销商在「对账单」看本期应收。

状态流转：草稿 → 已确认（占库存）→ 部分发货 / 已发货 → 已完成；可作废（未发货前）。

五、主数据

入口：左侧「主数据」

页面路径管什么关键点
商品档案/master/productsSPU + SKU、规格、条码、价格、安全库存一个商品多个 SKU（规格/色号）；改价影响取价链
组合装档案/master/bundles组合装（套装）与其成分拆解出库时按成分扣库存
品牌与品类/master/brands品牌、品类树品类决定报表维度
供应商 / 经销商/master/partners往来单位主数据连锁餐饮版没有经销商页签（业务形态差异）
仓库与门店/master/org仓库、门店、组织树仓库类型决定能不能卖、能不能存
条码 / 序列号识别/master/barcode条码规则、序列号查询序列号管理商品出库必须扫
出入库单据类型/master/inv-txn-types库存流水类型字典客户可自建类型；类型决定成本方向

操作要点

  • 新增商品：填 SPU 基本信息 → 加 SKU（规格/条码/价格/成本）→ 保存；
  • 改价：改 SKU 的零售价 / 经销商价 / 会员价；改完对已确认的订单不追溯；
  • 仓库类型：normal 正常仓、store 门店仓、defect 不合格品仓、quarantine 待检仓。

隔离类仓不参与铺货，货只能通过质检处置调进来。

六、采购管理

入口：左侧「采购管理」（11 个页面）

6.1 采购工作台

/purchase/workbench —— 按「请购 → 订单 → 收货 → 质检 → 发票 → 结算 → 付款 → 退货」九环节横排，

每一格显示待办数量，点进去就是对应列表。演示采购建议从这里开始。

6.2 请购单

/purchase/requisitions

字段说明
请购部门 / 需求日期谁要、什么时候要
明细（SKU / 数量 / 建议价）需求行
状态草稿 → 已提交 → 已审批 / 已驳回 → 已转订单

操作：新建 → 提交 → 审批 → 「转采购订单」（可改供应商与数量）。

6.3 采购订单

/purchase/orders

状态含义能做什么
草稿还没提交编辑、删除、提交
已提交待审批审批、撤回
已审批可以收货收货、关闭、作废
已收货全部收完关闭
已关闭归档（零副作用）—

关键字段：已收数量 / 订单数量、超收比例、结算方式、预计到货日。

部分到货怎么看：列表里「已收 / 订单」两列不相等 ⇒ 还有在途；收货单可能有多张。

6.4 收货单

/purchase/receipts

状态含义下一步
草稿收货动作未确认确认收货
已收货货已入库，待检质检
已质检检完关闭归档
已关闭归档—

操作：从采购订单「收货」→ 填本次到货数量（可小于订单数量）→ 确认 → 生成收货单 + 入库流水。

注意：收货数量超过「订单数量 × (1 + 超收比例)」会被拒绝（PO_OVER_RECEIVE）。

6.5 采购质检

/purchase/inspections（存量入口；新入口在「质量管理 → 质量中心」）

操作：选待检收货单 → 建质检单 → 逐行填合格 / 让步 / 判退数量 → 提交。

判退会自动生成采购退货单并出库。

6.6 采购发票 / 结算 / 付款 / 应付台账

页面路径说明
采购发票/purchase/invoices录入供应商发票，校验与入库的差异
采购结算/purchase/settlements按入库单/发票一单一结，生成应结金额；支持退货抵减（配置项）
付款单/purchase/payments登记付款、审批、执行
应付台账/purchase/payables按供应商汇总：已结算 / 已付 / 未付；退货单独一块

「应付」怎么算：本系统没有独立的应付子台账，应付 = 结算金额 − 已付金额。

退货不并进结算金额，而是单列披露 —— 要不要抵减由配置 purchase_return_offset 决定（默认不抵）。

6.7 供货目录 / 采购退货

页面路径说明
供货目录/purchase/catalog每个供应商能供什么、协议价多少
采购退货/purchase/returns退货出库；已确认/已完成才入账（凭证：借 2202 应付 / 贷 1405 库存）

九、质量管理

入口：左侧「质量管理 → 质量中心」/quality/qc

回答什么问题：这批货能不能用？不能用怎么处置？

质检来源：采购到货、生产完工、在库复检。

操作流程

  1. 待检列表里选一张来源单（收货单 / 完工单）；
  2. 建质检单（自动带到货明细）；
  3. 逐行填：合格数量 / 让步接收 / 判退数量（三者之和必须等于到货数量）；
  4. 提交 → 结论自动判定（全合格 / 让步 / 不合格）；
  5. 判退行生成采购退货单并出库；让步行按良品入库但留痕。

关键概念

  • AQL 抽样：按 AQL 2.5 / 检验水平 II 计算抽样量；
  • 不良品处置：返工 / 让步 / 判退 / 报废，四种处置都有库存后果；
  • 隔离仓：不合格品仓、待检仓。货只能通过处置调进来，不能直接铺货。

十一、财务应收

入口：左侧「财务应收」

11.1 应收与收款核销

/finance/receivables

区块内容
应收单按客户/按单/按账龄，状态：未收 / 部分 / 已收 / 已作废
收款单登记 → 确认；可指定核销哪几张应收
账龄0-30 / 31-60 / 61-90 / 90+
预收多收的钱停在预收，可转应收

操作（收到部分货款）

  1. 「登记收款」→ 选客户、金额、方式（转账/现金/票据/在线）；
  2. 指定核销的应收单与金额（不指定则按到期日先进先出）；
  3. 保存（草稿）→ 确认 → 应收余额减少、授信释放。

注意：核销金额超过应收未收余额会被拒绝（RC_ALLOC_EXCEEDS_AR），不会「悄悄截平」。

四个通用工具

工具作用
doc.list_types列出全部单据类型、状态、可推进边（区分安全边/高危边）
doc.query按类型/状态/关键词查单据（受实体范围约束）
doc.get查单据详情 + 完整流转留痕
doc.transition推进单据（高危边一律拒绝）

安全边界（六条）

  1. Agent Token：可吊销、限频、绑行业；
  2. 实体范围：组织 / 门店 / 经销商 / 仓库，越界当作不存在（不泄露"有但你看不到"）；
  3. 边权限：与界面同一份判据（assertEdgePermitted）；
  4. 高危动作：一律拒绝（EDGE_REQUIRES_HUMAN），必须人工确认；
  5. 幂等键：(token, tool, key)，同键异参返回 409；
  6. 全量留痕：每次调用都记，可在日志里查。

已知限制：7 种单据没有归属列（AR / CA / OCS / OM / RCP / RFD / VOUCHER），

受限令牌看不到它们 —— 控制台里打了「受限令牌不可见」标记，这是已知且已披露的限制。

18.1 新增一个用户

  1. 用户与权限 → 新增；
  2. 填账号（创建后不可改）、姓名、角色；
  3. 角色是 store 的必须绑定门店；dealer 的必须绑定经销商；
  4. 保存 → 用户可登录。密码用 bcrypt 存储，管理员可重置。

18.2 调整角色权限

  1. 角色与权限 → 左侧选角色；
  2. 右侧勾选功能权限（按模块分组，可整组全选/清空）；
  3. 「保存」→ 写审计日志；
  4. 下方「该角色登录后看到的菜单」实时预览。

注意：admin 角色权限不可在此修改，避免把「维护权限」这个权限本身删掉。

18.3 改业务参数

系统参数 → 选配置项 → 改值 → 填变更理由（危险项必填）→ 保存。

配置项的铁律：默认值 = 上线前的行为；改动留痕；未登记的键读写都拒绝。

19.2 常见错误码

错误码含义怎么处理
TRANSITION_NOT_ALLOWED当前状态不允许这个动作刷新详情，看当前状态与可用动作
