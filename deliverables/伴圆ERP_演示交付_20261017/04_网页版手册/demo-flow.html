伴圆AI原生ERP系统 · 完整演示手册

AI 伴你，企业信息化管理圆满 面向：销售 / 售前 / 实施顾问 ｜ 用途：对客户做 20~60 分钟系统演示 适用行业：美妆连锁版、连锁餐饮版（服装版开发中，不在演示范围）

一、演示前必须说清的三件事（开场 30 秒）

  1. 这是演示环境，数据全是虚构的。

商品、客户、门店、供应商、单据都由程序生成，不含任何真实客户与商业数据。

首页顶部有 DEMO 演示系统 标识，随时可以指着它说这句话 —— 主动说明比被追问出来强。

  1. 这是一个「多行业、同一套内核」的 ERP。

美妆连锁、连锁餐饮共用一套表结构与业务规则，登录时选行业即进入各自独立的数据库。

  1. 它把「任何单据」都开放给了 AI。

不是加了一个聊天框，而是 40 种单据、200 多条流转边都通过 MCP 暴露给 AI，

能查、能读详情与留痕、能在安全边上推进；高危动作一律拒绝，必须由人确认。

一句话定位（可直接照念）： 「这是一套 AI 原生 ERP：业务照常做，但每一步都能被 AI 读懂和操作，而且 AI 做不了的事它会明确拒绝。」

三、美妆连锁版演示脚本（主线，约 25 分钟）

主线逻辑：先让客户看到「生意在跑」→ 再拆「一张单怎么走完」→ 最后讲「AI 与权限」。 不要一上来讲功能清单，客户记不住，也不关心。

3.1 第一步：经营看板（3 分钟，admin 登录）

做什么：用 admin / 12345 登录 → 默认落在「经营看板」。

怎么讲（按屏幕从上往下）：

  1. 顶部横条：先指 DEMO 演示系统 —— 主动说明数据虚构，建立信任。
  2. 六个 KPI：本月销售额、订单、线上 GMV、库存金额、待回款、本月采购。

> 话术：「这六个数字是老板每天早上会看的，点进去都能追到明细单。」

  1. 待办事项：待发货订单 / 待收货采购 / 线上待发货 / 库存与效期预警。

> 话术：「系统不只是报表，它每天会告诉你今天该干什么。」

  1. 近 30 天销售趋势：线下与线上两条曲线分开 —— 强调「口径分开，不混着算」。
  2. 渠道结构：各渠道销售额占比，回答「钱从哪来」。

客户常问：「这些数据能改吗？」

答：演示环境随便改；真实部署时数据来自业务单据，不能手工填。

3.2 第二步：一张销售订单怎么走完（8 分钟，重点）

路径：销售管理 → 销售订单 → 找一张状态为「已确认」的单（列表里可以按状态筛选）。

要讲的四个动作（这四步就是销售的全部）：

动作点什么单据变成什么屏幕上要指的地方
① 发货（部分）订单详情 → 发货订单仍是「已确认」，但明细里的已发数量变了明细行「已发 / 未发」两列
② 开票（部分）发货单 → 开票发货单的开票状态 = 部分开票开票状态 + 已开票数量
③ 收款（部分）财务应收 → 应收与收款核销 → 登记收款应收单 = 部分核销，余额还在应收余额、已核销金额
④ 退货（可选）销售管理 → 销售退货生成退货单，库存回冲、应收冲减退货明细绑定的原订单行

这一段的杀手句： 「大部分系统只能演示『全发』或『没发』，而真实业务里 80% 是中间态。 你看这张单：发了 60%、开了 60% 的票、收了 40% 的钱 —— 三个状态同时存在，而且每一笔都能追溯。」

再补一句：发货单上的开票状态是服务层算出来的，不是人手填的 ——

所以不会出现「开了票但发货单还显示未开票」。

3.3 第三步：采购到入库（5 分钟，可切 scm 账号）

路径：采购管理 → 采购订单 → 选状态「已审批」的单。

要讲的三条线：

  1. 部分到货：订单上「已收数量 / 订单数量」不相等 ⇒ 剩下的还在路上。
  2. 收货单：状态「已收货」= 待检；「已质检」= 检完；「已关闭」= 归档。
  3. 质检：质量管理 → 质量中心 → 打开一张质检单，看「合格 / 让步 / 判退」三档数量，

判退会自动生成采购退货单并出库 —— 强调「一个有后果的动作，不是打个标记」。

话术：「采购最怕的不是没到货，是『到了但不知道能不能用』。 这三张单（订单、收货单、质检单）把这件事说清楚了。」

顺带带出：采购结算 → 应付台账。指一下「退货抵减」这一列：

「退货要不要冲减应结，是贵司的会计政策。系统里做成了参数：默认不抵，打开才抵， 而且每一笔改动都留痕、要写理由。」

3.4 第四步：门店零售与日报（5 分钟，切 store01）

两个界面都要看：

  1. 总部视角：线下门店 → POS 运营监控

- 「零售日报」按天列 —— 连续 22 天每天都有数，不是只有今天；

- 长短款：现金短款、微信渠道差异分开列（不同渠道的差异含义不同，不能合成一个总数）；

- 缴款单：已接收 / 待接收两种状态都在。

  1. 店长视角：新开标签打开 /pos

- 收银开单（扫码/选商品 → 收款）；

- 交班报数 → 店长核款 → 长短款归属（门店承担 / 收银员承担）；

- 日结上传到总部。

话术：「门店最怕两件事：钱对不上、货对不上。这一页一天一结，把钱和货都钉住。」

3.5 第五步：经销商与渠道（3 分钟，仅美妆/服装）

路径：经销商管理 → 经销商总览 / 返利管理 / 对账单。

  • 经销商总览：每家经销商的销售额、回款率、信用占用；
  • 返利管理：计提 → 确认 → 核销（核销会冲应收）；
  • 对账单：出具 → 结清 / 作废。

切 dealer01 登录：菜单只剩订货中心与对账 —— 让客户看到「同一个系统，经销商只看到自己的东西」。

话术：「这不是给他隐藏菜单，是数据范围就限定在他自己这家。」

3.6 第六步：财务与业财一体（3 分钟，可切 finance）

路径：财务应收 → 应收与收款核销 → 财务中心（凭证 / 试算平衡）→ 财务报表。

  • 应收：按客户、按单、按账龄；
  • 凭证：由业务单生成（不是手工录），点开一张凭证能看到「来源单号」；
  • 试算平衡：借贷必须平；
  • 报表：资产负债表 / 利润表 / 现金流量表，口径可追溯。

话术：「业财一体的意思是：凭证不是财务另录一遍，是业务单据自己长出来的。 所以业务和账永远对得上。」

3.7 第七步：AI 与 MCP（收尾，3 分钟）

路径：AI 与 MCP 控制台（仅 admin 可见）。

按四个页签讲：

  1. 单据矩阵：40 种单据全在，每种单据有哪些状态、哪些动作 AI 能推进、哪些必须人工。
  2. 工具清单：4 个通用工具 + 36 个领域工具。
  3. 安全边界：令牌、实体范围、边权限、高危确认、幂等、留痕 —— 六条。
  4. 接入方式：把 MCP 端点与 Token 交给客户的技术团队。

收尾话术： 「我们不是做了个 AI 聊天框。我们把每一张单据都开给了 AI —— 40 种单据、200 多条流转边。 但高危动作它做不了，会直接报 EDGE_REQUIRES_HUMAN，必须在界面上由人点。 这页上的数字不是写死的，是系统实时算出来的：你们以后自己加单据，它也会自动多一行。」

3.8 收尾：一句话总结 + 留资料

「业务上它是一套完整的进销存 + 财务 + 门店 + 经销商系统； 架构上它是 AI 原生的 —— 单据、状态、权限都能被 AI 读懂，也都能被人管住。」

然后打开首页最下方的 完整演示手册 / 功能模块操作手册，说明「这两份资料留给你们，可以自己按图点」。

四、连锁餐饮版演示脚本（约 15 分钟）

餐饮与美妆共用一套内核，演示时不要重复讲功能，只讲差异。

4.1 三处差异必须先说

维度美妆连锁连锁餐饮
分销层品牌方 → 经销商 → 门店总部 → 直营门店（没有经销商）
商品规格 / 色号，效期以月计杯型 × 冷热 × 加料，效期以天计
门店数量5 家（演示库）20 家（演示库）

4.2 演示顺序（与美妆相同的主线，跳过经销商）

  1. 经营看板：门店数更多、单店产出更小 —— 强调「多门店汇总口径」。
  2. 存货管理 → 库存预警 / 库龄：餐饮最关心临期。

> 话术：「餐饮的效期是按天算的，所以预警阈值和批次策略跟美妆不是一套参数，

> 但这些参数是配置项，不是写死的代码。」

  1. 采购 → 收货 → 质检：生鲜到货的让步接收（比如品相不好但可用）。
  2. 门店 POS → 零售日报：20 家门店 × 连续 22 天，按天按店都能拉出来。
  3. AI 与 MCP 控制台：同样的 40 种单据 —— 强调「换行业不用换架构」。

4.3 餐饮演示的注意事项

  • 不要提经销商：菜单里没有，提了客户会问「为什么我没有」；
  • 不要说「暂缓」：服装版叫「开发中」；
  • 餐饮门店多，POS 运营监控默认按天聚合，演示时先按「日」看，再切到单店。

五、按角色的演示路径（客户指定要「自己点」时用）

5.1 admin（系统管理员）

经营看板 → 销售订单 → 采购订单 → 库存 → 财务 → AI 与 MCP 控制台 → 系统管理

重点：全链路与配置能力（系统参数、角色与权限、单据内核、编码规则）。

5.2 scm（供应链主管）

经营看板 → 采购工作台 → 采购订单（部分到货）→ 收货单 → 质检 → 库存查询 → 调拨 → 盘点

重点：「一个人管采购 + 库存 + 生产 + 质检」—— 菜单里没有财务与系统设置。

5.3 store01（门店店长）

/pos 收银 → 交班报数 → （换 admin 核款）→ 缴款 → 日结 → 门店盘点

重点：钱和货都对得上；菜单里没有采购、财务、经销商。

5.4 dealer01（经销商）

订货中心 → 我的订单 → 对账单

重点：只看自己的数据；菜单里没有内部管理功能。

5.5 finance（财务）

应收与收款核销 → 财务中心（凭证）→ 财务报表 → 报表口径

重点：凭证由业务生成、借贷必平、口径改动留痕。

5.6 viewer（只读访客）

经营看板 → 库存 → 销售订单（看但不改）

重点：让客户自己点，点坏了也不影响数据。

六、常见追问与标准回答

客户会问怎么答（可直接照念）
数据是真实的吗？不是。全部由程序生成，首页顶部有 DEMO 标识。真实部署时数据来自业务单据。
能对接我们现有的系统吗？有两层：REST 接口（/api/*，有完整 OpenAPI 契约）与 MCP（给 AI 用）。两边共用同一套领域服务与权限判据。
AI 会不会乱改数据？不会。AI 走 MCP，高危动作一律拒绝（EDGE_REQUIRES_HUMAN），安全边也必须过与界面同一份权限判据；每次调用全部留痕。
支持多组织 / 多门店吗？支持。组织树 + 数据范围（全部 / 本组织及下级 / 本组织 / 本经销商），门店、仓库、经销商都挂在组织上。
权限能细到什么程度？到权限点。137 个权限点，按角色分配；菜单只是界面收敛，接口层另有判据。
能改业务流程吗？单据状态机在内核表里（doc_types / doc_states / doc_actions），可以加状态与动作；参数类规则（会计政策、库存口径、退货抵减）做成了配置项，改完留痕。
服装版呢？开发中。技术上与另两个行业同构，演示入口暂时不展示。
数据能导出吗？列表页支持导出 Excel；接口层也有导出能力。

七、演示翻车急救

现象原因处理
页面全空白 / 接口 401登录态过期重新登录；或清 localStorage 后重进
列表是空的筛选条件卡住了（比如状态选了「草稿」）点「重置」清筛选
