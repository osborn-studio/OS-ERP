### 3.1 技术要点（接手前必知）

- **多行业库**：同一套表结构，按行业各一份 SQLite 库（美妆 / 餐饮 / 服饰）。登录时选行业 → JWT 带 `industry` 载荷 → `AsyncLocalStorage` 自动切库 → 业务路由**零改造**。
- **当前规模（2026-10-16 00:55 实测）**：迁移 **26 个**（001…025 + 助手/运行器）；后端 **41,937 行**（32 路由 / 27 服务层）；前端 **30,647 行**（`src/pages` 20 个目录 / 71 个 `.tsx`）；脚本 **13,492 行**（44 个 `.mjs`）；开放接口 **399 条路径**；契约版本 **1.14.0**；仓库 **55 个提交**。
- **业务日期只有一个出处**：`server/lib/dates.js` 的 `localDate()` / `localNow()`。**禁止**用 `new Date().toISOString().slice(0,10)` —— 那是 UTC 日期，东八区在本地 00:00–08:00 之间会比本地日期早一天，造成「JS 侧说不逾期、SQL 侧说已逾期」而同为 200 的静默错误。
- **单据内核**：所有单据类型注册在 `server/db/migrations/008_doc_kernel.cjs`。**新增单据类型必须同时改这里**，流转一律走 `applyTransition`，不在路由里散写状态字符串。
- **新增表必须登记进 `seed.js` 的 `TABLES`**，否则整库重建后旧数据跨代残留、引用已被复用的 id。
- **「重建」要的是可复现，不是"清掉看得见的表"**：凡参与 `ORDER BY` 或作为对外标识的派生状态（如取号计数器）也必须进重建清单。
- **错误码两段式**：顶层 `code` 数字（0 成功 / 1 失败），业务错误码在 `detail.code`。

## 5. 交付物体系（`~/工作文档/` 顶层）

- **命名规则**：`00_<主题>_<版本>_<日期>.docx`（`00_` 前缀保证排在目录最前，代表"当前有效成品"）。
- **数量**：顶层共 **262 个** `00_*` 文件。
- **双格式铁律**：同一份内容的 MD 原稿存 `gml/docs/`，Word 副本存 `~/工作文档/` 顶层。两者必须一致（改完用 `cp` + `cmp` 校验）。
- **转换管线**：`/tmp/md2docx_generic.py <源MD> <目标DOCX>`。
  - 局限：粗体标记不能跨行（逐行成段，跨行收不掉会在 Word 里留下字面星号）；一行里不要写不成对的反引号。
- **实时编辑已打开的 Word**：先按路径取 UUID，表格用单元格接口、文本用查找替换（含引号的长串会静默不中，改用不含引号的短子串）。

另有一份**固定路径、覆盖式**的文件：`~/工作文档/00_GML董事会群播报.md` —— 每期报告覆盖写入，供发群取用。

### 8.3 全量回归（**必须串行**）

驱动脚本：`scripts/regress-all.mjs`（它把「哪些测试要 × 三库」**从源码里读出来**，而不是靠人记）。

判定依据是**该测试有没有读 `process.argv[2]`**（本项目「行业参数」的约定）：读了 = 三库各跑一遍；没读 = 单库跑一遍。

| 组成 | 套数 | 命令数 |
|---|---|---|
| `test-*.mjs` 跑三库（读 `argv[2]`） | **15 套** | 15 × 3 = **45** |
| `test-*.mjs` 单库（不读 `argv[2]`） | **6 套** | **6** |
| 自检脚本（`verify-seed all` / `verify-migrations` / `check-api-contract` / `smoke-api`） | 4 | **4** |
| 类型与构建（`tsc --noEmit` / `vite build`） | 2 | **2** |
| **合计** | **21 套测试** | **每轮 57 个 `rc=0`** |

**默认跑 3 轮** → 171 个 `rc=0`。`reusable/test-reusable.mjs`（31 条断言）**不在 `regress-all` 内**，需单独跑。

调速开关：`ROUNDS=1 node scripts/regress-all.mjs`（改一处时用）、`ONLY=promo …`（只跑文件名含关键字的测试）。

```bash
node scripts/regress-all.mjs              # 默认 3 轮（约 171 个 rc=0）
ROUNDS=1 node scripts/regress-all.mjs     # 单轮
```

**为什么必须串行**：**三个行业 = 三个独立的 SQLite 文件**（`data/gml_{cosmetic,food,apparel}.db`），但**同一个库会被多个测试脚本写**。并发跑同一库会 WAL 竞争，报出来的错与真实原因无关（本项目已踩过）。`regress-all` 内部就是 `spawnSync` 逐个串行。

**测试脚本硬规则**：

1. 必须能**重复跑**（开头清自己上一轮的残留，涉及库存的用库存快照回滚）。
2. **不得留下副作用**：曾在 `test-pricing` 里 `DROP TABLE promotions` 建假表，结果同一轮的 `test-promo` 报 `no such table`。现在的写法是**假表只活在事务里 + 收尾断言真实表还在**。
3. **活跃档禁止跑写库类测试**：另一对话正在实时灌数时并发跑，会与对方冲突并产生误判 —— 此时只做只读校验。

### 10.2 改动时的硬规则

| 规则 | 原因 |
|---|---|
| 数据库先行，一批一迁移 | 表结构定不下来不动代码 |
| 迁移必须**幂等 + 带 verify** | 运行器能在结构脱节时自动重跑修复 |
| 新增单据类型 → 改 `008_doc_kernel.cjs` | 否则状态机不认 |
| **新增内核类型前先全库检索短码** | 曾出现计划中的短码已被占用，按计划注册会静默覆盖 |
| 新增表 → 登记进 `seed.js` 的 `TABLES` | 否则整库重建跨代残留 |
| 测试串行 + 可重复跑 | WAL 竞争 / 残留污染 |
| 前端调接口**不用模板串拼接** | 契约检查靠静态扫描，拼接会被误报 |
| 「数量」与「金额」**不共用舍入函数** | 金额 2 位，数量 4 位（有 kg） |
| 测试随机失败**先做成可复现再排查** | 不接受"重跑一次就过了" |
| 弹窗嵌套里任何 `onClose`/`reset` **先问"谁还在读这份 state"** | 曾导致假界面全 0，且通过了全部自动化测试 |
| 截图交付**必须 md5 查重** | 防同内容不同名 |

## 11. 脱敏与合规铁律

1. **真实客户名与品牌名一律不出现在任何产出中** —— 含系统界面、演示 seed 数据、官网、交付文档、PPT、截图、代码注释。
2. 产出中一律用行业中性名：美妆线 → **美妆版**；餐饮线 → **餐饮版 / 连锁餐饮**。
3. 演示数据（门店名、商品名、供应商名、会员名）必须**自行虚构**，不得使用真实品牌谐音、不得影射真实品牌。
4. 生成前端文案 / seed 数据 / 文档 / 截图之前，**提交前自查敏感词**。
5. **不越级定性**：BP、Demo、方案、口头人天，不得写成"已上线 / 已验收 / 已签约 / 已回款"。
6. 本系统为**演示与方案验证用途**，数据由程序随机生成；用于生产前需替换鉴权密钥、接入真实主数据并做安全加固。
