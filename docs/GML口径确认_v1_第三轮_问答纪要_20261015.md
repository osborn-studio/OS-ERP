## 二、逐条记录（含原话要点）

### A 组｜MCP 能力层边界

**A1 开放程度 —— 含写，三级分类**（用户定）

| 级别 | 范围 | 规则 |
|---|---|---|
| 查询类 | 库存、单据、报表、主数据读取 | 全开 |
| 事务类 | 下单、出入库、调拨、发起审批 | 开放，但**强制幂等键** |
| 高危类 | 付款、调价、作废、审批通过 | **必须人工二次确认** |

**A2 / A3 / A4** —— 按建议：独立 Agent Token、绑定单一主体、对外只讲"已实现的全部业务能力"。

---

### B 组｜组织与主体（本轮最重要的新增信息）

**B1 主体层级 —— 四层**

```
总部（法人）
  └─ 区域
       └─ 门店（直营 / 加盟）
            └─ 仓 / 中央厨房
```

**B2 加盟店 = 独立主体**：自有货主、独立结算、独立账；与总部是**交易关系**（不是内部调拨）。

**B3 中央厨房 = 总部下的仓库 + 生产车间**：不独立核算，成本并入总部。

**B4 餐饮采购 = 总部统采为主 + 门店零星自采**：主材总部管，门店可临时小额自采。

**B5 美妆经销商 = 两级都可开户**：经销商公司与其旗下门店都能订货，门店可挂在其公司下。

---

### C 组｜价格与成本

**C1 价格组 —— 四维自由组合、不设主维**（用户定）

四个可用维度：渠道 / 门店类型 / 经销商等级 / 区域。
落地方式：**价格组 = 命名组合 + 优先级排序**（避免笛卡尔积爆炸，用命名与优先级管理）。

**C2 / C3** —— 按建议：取价顺序固定；成本规则现在定文字、模块 09 落实现。

---

### D 组｜做到什么程度（均按建议）

- **D1 POS 离线模式：做** —— 断网可继续收银，恢复后上传补单。
- **D2 支付：模拟支付 + 预留真实支付接口**（与"不越级定性"一致）。
- **D3 WMS / 物流 / 税务 / 平台订单：接口占位 + 模拟回传**，本次只演流程。
- **D4 商城：本期只 H5**，小程序留入口。

---

### E 组｜审批与账号

**E1 首做 IM —— 钉钉 + 飞书都要**（用户定）
策略不变：**方式 B（H5 跳转）1 套打三家**为主；**方式 A（原生审批单）先做一家样板**，另一家随后补。具体先做哪家，待客户实际情况定。

**E2 / E3 / E4** —— 按建议：金额档位示例（可配）、系统内审批矩阵为主、做手写签名。

## 三、本轮新增口径（前两轮未涉及）⭐

### 3.1 跨地区运营：内地 + 中国香港

- 餐饮版含**中国香港门店** → 需支持**多币种**（人民币 / 港币）+ **多税制** + 跨地区报表。
- **传导**：组织加「地区 / 币种」属性；单据与报表带币种；税率按地区配置。
- **影响**：进入 P0 数据模型 —— 新增 `regions`（地区）+ `currencies`（币种）+ 地区税率配置。

### 3.2 品牌维度进入组织与商品

- 餐饮版 **3 个品牌**：
  1. 日式丼饭快餐
  2. 烤肉 + 火锅
  3. 传统中餐
- **传导**：组织、商品、库存、报表均需带**品牌**维度（品牌可跨区域、跨门店类型）。
- ⚠️ **品牌名一律虚构**，不得与任何真实品牌谐音或影射。

### 3.3 价格组：四维自由组合

- 定案：不设主维 → 需**「价格组优先级 + 取价规则引擎」**。
- 演示期用命名组合管理（如"华东·加盟·银牌"），后台可排序。

### 3.4 中央厨房定性带出的生产与转移口径

- 央厨 = 仓库 + 生产车间 → **生产订单挂央厨仓**，领料与完工入库均发生在央厨仓。
- ⚠️ 加盟店是独立主体 → 央厨半成品给加盟店属**货权转移**，须走**销售 / 调拨（带结算）**，不能简单内部调拨。

### 3.5 门店可零星自采

- 采购需支持**门店级采购申请**（小额），总部审批后执行。
- **传导**：请购单带「申请主体」；采购订单需能关联到申请门店。
