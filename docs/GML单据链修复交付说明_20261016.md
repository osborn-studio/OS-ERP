## 三、新登记的环境/方法学教训（**比单个 bug 更可复用**）

1. **一条判据可以给出反向激励**：内核 `008.verify()` 的"终态不能有出边"让"把 `returned` 定成不可逆终态"这种错定义**反而通过自检** —— **定义错得越彻底，自检越绿**。
2. **"隔离"会在三种进程关系上同时失效**：① 脚本**硬编码 `ROOT/data`**（`GML_DATA_DIR` 对它完全无效 —— 本轮共 **15 个可写 + 4 个只读**）；② 只把 env 注给 `spawn` 的子进程，**父进程自己**仍落 `data/`；③ spawn 的服务端**不回收**。
   ⇒ **通用手法（两条，后者更硬）**：**① 结构上让 `ROOT` 跟着搬**（把脚本/整棵树复制或软链到 `/tmp` 下再跑，硬编码也跟着走）；**② 环境上让指错当场失败**（未设或指向仓库 `data/` ⇒ `exit 2`）。**"人记得就不出错" < "想出错也出不了"。**
3. **口径卡的"键"必须是真实响应码** —— 本轮曾把两个语义 id 当成真实码写进卡片（"映射存在但永远命中不了"）；已改回**统一语义 id**，并把"若将来接到真实码上须整表一起迁移"写成待定。
   **⚠️ 更正（该路自查）**：它**第一份报告里那几处 `file:line` 经自查不是仓库里的东西**（只能当线索）⇒ 因此"口径卡前端无人渲染"这个判据**建立在不存在的读取上，已收回**。**正确现状**：`rules` **前端未接线、但生产可达**（`GET /api/manufacture/meta`，`routes/manufacture.js:145-158`）；且**字段形状与前端期望不一致**、`errText` 在 `MfgCenter` 里有**两套读法**。⇒ 低危但潜伏，**已记为"口径卡未形成可持续维护路径"**。
4. **`doc_type` 这一列没有权威字典**（无 CHECK、无外键、16 种取值、两字典交集 0）⇒ 已加常驻守卫 `scripts/check-inv-txn-dict.mjs`（`doc_type ⊆ inv_txn_types ∪ doc_types` + `txn_type` 非空 **强制**；单号前缀 `--strict` 默认关）。它上线第一天就捞出**新 bug**：拆卸单用 `DS`，而 `DS` 是**经销商对账单**的注册前缀 ⇒ 库里两种 `DS` 单同时存在。
5. **"验证"有一个时间窗，窗口里工作区必须静止** —— 三种形态：**加载时**（子进程 require 到半写模块）· **复制时**（`cpSync` 拍到半成品快照）· **探活时**（`exit` 钩子里 `kill(pid,0)` 必报"仍在"⇒ **假红**）。⇒ 验证类动作只在**工作区静止**时做。
6. **热库取副本 = `.db` + `-wal` + `-shm` 一起拿**；**只读判定看内容（sha256）而不是 mtime**（只读打开会 touch `-shm` 但不改内容；WAL 未 checkpoint 时主库可能因 checkpoint 时序而变）。
7. **写作纪律**：**"同一句话的两个版本"本身就是缺陷** —— 凡出现"（已作废）/（supersede）/（FINAL）"叠加，就说明**改的人比读的人多**；一条信息在文档里只能有**一个当前版本**，且**由文档 owner 一个人改**。
8. **转述必须核出处**：本轮出现过 4 次"把别人说的当成已核实的"（记错改动归属 / 记错数字出处 / 把推断当引用 / 转了两个**全仓 0 命中**的错误码）。**"记一个没做过的改动，和记一个查不到的数字，是同一种错。"**
