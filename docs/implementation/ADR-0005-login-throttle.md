# ADR-0005：有界、持久化的后台登录节流

日期：2026-10-22。范围仅限后台账号登录；不是商城、MCP 或全站流量防护。与会话撤销核心顺序集成，由认证路由调用本模块。

## 决策与契约

使用 `GML_DATA_DIR/login-throttle.sqlite`，单独持久化节流状态，不占业务迁移编号。所有行业共用此文件，因此来源 IP 限额不会被切换行业绕过。库沿用 production/demo/test 分类保护，拒绝运行模式不符或未分类的旧库，不自动删除或重分类。三个模式都启用相同限制。

路由先校验输入类型、长度并按实际查询语义规范化账号及行业，然后在查询账号和 bcrypt 比较前调用同步 `consumeLoginAttempt({ip, industry, username})`。成功返回 `{allowed:true}`；限额或容量耗尽抛出 `429 / LOGIN_RATE_LIMITED`，附正整数 `retryAfter` 秒，路由写入 `Retry-After`；存储、配置或策略冲突统一 `503 / LOGIN_THROTTLE_UNAVAILABLE`，不回退内存或放行。非法内部接口输入为 `400 / LOGIN_THROTTLE_INPUT_INVALID`。模块不接收密码作为业务参数、无日志输出、不保存登录结果。

两个维度在同一 `BEGIN IMMEDIATE` 事务中检查并登记：

- IP：跨行业、跨账号共享。IPv6 表达式规范化，IPv4-mapped IPv6 与对应 IPv4 合并。
- 行业 + 账号：跨 IP 共享。账号保持实际 `users.username=?` 的大小写敏感语义；路由负责 trim，模块不私自 casefold。不存在账号同样计数，不能用查库结果选择性绕过节流。

成功和失败的密码验证都消耗登录尝试预算；成功不清空计数，避免登录成功重置另一维度。任一维度被拒绝时不更新计数或延长窗口，也不为其他新键分配空间。单次事务失败整体回滚，不能只登记一个维度。SQLite 写锁等待最多 1 秒，超时拒绝该次登录；同步等待会占用 Node 事件循环，应在目标负载测试中测量这一代价。

## 默认策略与调整

| 环境变量 | 默认 | 合法范围 |
|---|---:|---:|
| `GML_LOGIN_IP_LIMIT` | 60 次 | 1–10,000 |
| `GML_LOGIN_IP_WINDOW_MS` | 60,000 毫秒 | 1,000–86,400,000 |
| `GML_LOGIN_ACCOUNT_LIMIT` | 10 次 | 1–10,000 |
| `GML_LOGIN_ACCOUNT_WINDOW_MS` | 300,000 毫秒 | 1,000–86,400,000 |
| `GML_LOGIN_MAX_BUCKETS` | 10,000 个键 | 2–100,000 |

这些是保守的初始工程默认值，**没有生产容量测量依据**。需用企业规模、共享出口 IP/NAT、预期登录重试、机器资源和告警数据在目标 Linux 上验收后调整。限制对象是尝试次数，不是并发会话数。测试模式不会自动提高或关闭限制；长回归需使用隔离数据目录/专用账号，必要的显式测试阈值必须记录。

采用从首次获准尝试开始的固定窗口；接近边界时可能连续获准两段窗口的预算，不能宣传为任意滑动时间段的严格上限。没有永久锁号，受限后可在窗口到期重试。时间来自服务端 `Date.now`，测试用工厂接口注入时间；客户端不能控制时间。系统时钟向前跳跃可能提早到期，向后跳跃可能延长限制，部署应维护可信时钟同步。

每次消费和初始化只删除已经到期的键；达到容量时不淘汰任何活动键，为新随机账号腾空间会让攻击者清除已有限制。容量拒绝同样返回 429，`Retry-After` 指向最早到期时间，表示下次可重试，并不保证当时有足够空间。默认最多 10,000 个活动键，允许已有键继续在自己的预算内使用。随机账号/多来源洪泛仍可能使新登录暂时不可用，这是 fail-closed 取舍；需要边缘流量控制、可用性告警和容量规划，不能仅凭此模块宣称抵御分布式拒绝服务。SQLite 文件可能保留曾分配页面，键数量上限不等于严格磁盘字节上限。

策略存入元数据。只要存在活动键就禁止改变策略，防止重启或不同进程配置覆盖已有预算；配置错误会导致 503。需要修改时先排空登录入口，等待当前最长窗口到期后以一致配置启动所有进程；不要删除数据库当作正常调参或解锁步骤。窗口到期后新策略可以写入，仍持有旧策略的连接会拒绝继续消费，需要统一重启。当前版本不提供动态管理界面。

## 持久化、隔离与隐私边界

同一实例、同一绝对数据目录下的多个连接/进程共享 SQLite 原子事务；关闭连接或重启进程不重置状态。WAL 与 `synchronous=FULL` 降低正常进程退出/崩溃造成未持久化记录的风险，但本批没有做断电或文件系统损坏实验。此设计不支持各主机使用独立目录的全局限额，不承诺网络文件系统共享 SQLite。多主机部署应改用具有原子操作和一致 TTL 的集中式存储，再重新验收。

键用每库随机 32 字节盐值做 HMAC-SHA256；表内仅保存不透明键、次数、到期毫秒及策略/盐/模式元数据，不保存原始 IP、账号、密码或 JWT。新库权限 0600，新建数据目录 0700；已有目录权限由部署者负责。盐与库一起保存，故 HMAC 是降低直接暴露的假名化，**不是匿名化或数据库加密**；获得完整库文件的人仍可对已知候选身份做字典匹配。备份包含此安全状态，需按敏感运行数据保护；恢复过旧备份会回退限制，不得宣称防管理员或文件系统级篡改。

当前 Express `trust proxy` 默认关闭，路由使用 `req.ip`（socket 来源）而不读取客户端 `X-Forwarded-For`。因此任意伪造该头不能更换 IP 键。未来接反向代理必须显式限定可信代理地址/跳数并验证真实网络拓扑；简单全局信任客户端转发头会破坏此保证。代理部署下如果不配信任策略，所有用户可能共享代理 IP，需在上线前明确验收，不能临时相信任意转发头来绕过限制。

## 实际验证与未完成边界

Mac mini Node 22 开发焦点命令：

```sh
PATH=/opt/homebrew/opt/node@22/bin:$PATH GML_RUNTIME_MODE=test node --test tests/login-throttle.test.mjs
```

本模块初次执行结果 **15 个测试通过，0 失败，0 跳过**：默认模式仍受限；跨行业 IP/跨 IP 账号；大小写及 IPv6 等价表达；毫秒边界和 Retry-After；关闭重开；12 个独立并发进程对 5 次预算恰好 5 允许/7 拒绝；容量洪泛不淘汰活动限制；到期回收；原始身份/凭据不落盘；运行模式/未分类旧库保护；触发器注入写失败的两维度回滚；写锁争用返回 503；策略变更拒绝及旧连接失效；无效配置 fail-closed。测试全部新建临时目录，清理连接及自有文件，未运行 Python。

这些是模块开发检查，不代表 Linux 目标平台验收、HTTP 路由接线或商用上线通过。伪造转发头、输入规范化、统一登录失败响应、bcrypt 前消费及 Retry-After HTTP 响应由会话核心的 HTTP 专项验证；Linux 焦点/三轮完整回归由主线程在 dmserver 执行后记录。仍需评估共享 NAT 的正常用户误伤、持续登录负载下的同步 SQLite 开销、磁盘耗尽告警、反向代理部署及备份恢复策略。
