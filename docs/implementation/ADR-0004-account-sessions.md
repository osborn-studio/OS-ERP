# ADR-0004：后台账号会话版本与原子安全变更

日期：2026-10-22。范围：F06 后台身份；不包含 F07 Agent Token 撤权、单设备会话、refresh token 或生产上线验收。

## 会话契约

新增迁移 050，为 users 添加非负整数 `auth_version`，初值零。迁移只补列，重复执行不重置已有版本。后台 JWT 必须携带该整数版本及有效行业，签发/验证只使用 HS256，保持 `gml-erp` audience 和原有 12 小时期限。

`requireAuth` 仍然每次读取当前用户权限/状态；账号不存在、非 active 或版本不匹配返回 401 `SESSION_REVOKED`。无版本旧 JWT、错误类型/负数版本拒绝，不提供版本零兼容。升级后所有旧会话需要重新登录。合法行业头与签名 Token 行业不同时仍以 Token 行业为准，不改变原行业路由契约。

改密、管理员重置、启用/停用、角色、超级管理员标记、组织、数据范围、经销商/门店归属实际变化，增加目标版本；姓名/部门/电话变化不自动撤销。主角色变化同步 primary user_roles；主组织变化清掉旧 user_orgs 并只重建所选组织的 member 关系，避免遗留额外范围。保留未更改的其他角色关联，主角色调整不等于删除所有附加角色。

角色权限集合实际变化时，撤销以该角色为主角色或在 user_roles 关联该角色的全部账号，包含停用账号；无变化不增加版本。权限来自数据库当前状态。普通启动不应重新授予被管理员删除的权限，相关默认配置迁移修复另见 ADR-0007。

## 原子性与竞争

`account-security.js` 统一处理账号新增/更新、改密、撤销全部会话和角色权限变更。字段变更、版本、角色/组织关联与严格安全审计在同一 immediate 事务中提交。安全审计失败抛 503 `SECURITY_AUDIT_UNAVAILABLE` 并回滚，不复用吞异常的通用 audit。

密码哈希计算使用 bcrypt 异步接口、cost 12，在事务之外进行，提交时重新核对操作人的活动状态/版本/管理员权限，以及目标账号原版本和密码哈希。竞争败者返回 409 `ACCOUNT_CHANGED`，不能覆盖已经完成的安全变更。异步登录密码比较后也复读用户，拒绝比较期间已经改密、撤销或停用的账号。

版本达到 JavaScript 安全整数上限之前拒绝变更，不溢出回零。此方案不防有文件写权限的人直接篡改 SQLite；直接 SQL 跳过服务不自动递增版本。普通接口的每次回库检查仍提供当前状态/权限保护。

## 密码与登录

`password-policy.js` 是新设密码的唯一纯校验，供 bootstrap、新建、管理员重置、自助改密共用：至少 16 Unicode 字符、最多 72 UTF-8 字节、至少 6 种字符、无控制字符。旧账号登录保留原密码兼容，不把新强度规则强加到已有哈希验证；登录密码输入上限 1024 字节以限制请求成本。

登录严格验证字符串类型、账号长度和控制字符；账号 trim 后按原大小写查询，与节流账号键相同。不存在、停用、错密码统一 401 `AUTH_INVALID_CREDENTIALS`。不存在账号也比较公开的预制 dummy hash；它不是任何账号的凭据。不同历史哈希成本与网络仍可能造成时延差异，不声称恒定时间。

限速在 bcrypt 之前登记，覆盖成功/失败尝试，429 设置 Retry-After，节流存储不可用时 fail closed。持久化、有界容量和重启行为见 ADR-0005；应用保留 Express 默认不信任代理，直接伪造 X-Forwarded-For 不改变 req.ip。

## API 及操作边界

- `POST /auth/change-password` 输入 `{oldPassword,newPassword}`，成功 `{changed:true,reauthenticate:true}`，包括当前会话在内全部失效。
- `POST /auth/logout-all` 成功 `{revoked:true}`，撤销账号所有后台会话。没有单设备退出承诺。
- `PUT /auth/users/:id` 返回 `{id,sessionsRevoked}`；profile-only 修改不无条件踢人。
- `PUT /auth/roles/:code/permissions` 返回 `{role,permissions,revokedUsers}`。
- 后端 401 失效体验由独立前端任务接入，见 ADR-0008；此文不代表前端已验收。

未实现最后一个管理员的停用/降权保护或远程账号恢复；管理员需保留恢复方案。日志不记录密码、哈希或 Token，安全审计仅记录字段名、布尔变更标记及影响数量。

备份恢复会回退数据库内版本；恢复/回滚必须轮换 JWT 密钥或实施等价全局撤销。旧应用忽略版本，不能直接把回滚代码当安全恢复。上述运营验收仍属 F12。本批也不修复其他模块的所有通用审计失败行为。

## 验证入口

`node --test tests/auth-session.test.mjs`：多会话改密、管理员重置、启停不复活、权限/组织变更、角色成员影响、并发 CAS、安全审计回滚、统一失败/账号节流、退出全部、旧 JWT/算法/行业拒绝、迁移版本保持与重启权限保持。新密码共用规则还需运行原 bootstrap 专项。

只在新临时数据目录与随机 loopback 端口运行；合成凭据不输出。Node/macOS 焦点检查仅为开发证据，Linux/dmserver 完整集成与三轮回归由主线程记录。

开发验证记录：Node 22.22.1，12 项会话测试与 9 项 bootstrap 测试联动 21/21 通过；随后增加 2 项 HTTP 并发/伪造代理头及重启节流测试，2/2 通过。独立静态复审指出新增账号在异步哈希后需再核对主体状态，已补事务内复核及反例，该反例与并发 CAS 相关复跑 2/2 通过。最终会话专项共 15 项；固定候选整体结果以主线程 Linux 集成记录为准。
