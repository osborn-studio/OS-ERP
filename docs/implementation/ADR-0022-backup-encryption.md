# ADR-0022：备份加密与三库一致点

日期：2026-10-23。承接 ADR-0009（备份校验）与 ADR-0016（恢复演练）。范围：`scripts/db-backup.mjs`、`scripts/lib/drill-common.mjs`、`scripts/db-restore-drill.mjs`、`server/lib/backup-crypto.js`、运维手册第 1.1 节。

## 问题

1. 备份文件是明文 SQLite，含密码哈希、令牌哈希、渠道密文、客户资料；备份盘/拷贝一旦外泄等于全库泄露。
2. 三个行业库是顺序备份，各自在不同时刻，报告没有任何"这三份属于同一时刻"的说明。

## 决定

### 加密

- `GML_BACKUP_KEY` 未设置：行为不变。设置且 ≥32 字节：输出 `<库>_<stamp>.db.enc`。设置但过短：退出码 2（不静默降级为明文）。
- 格式 v1：`"OSBK" | 0x01 | salt(32) | iv(12) | 密文 | tag(16)`。整个 header 作为 GCM AAD，改动任何头部字节解密即失败。
- 密钥派生：文件密钥 = HKDF-SHA256(`GML_BACKUP_KEY` 的 UTF-8 字节, salt=每文件随机 32 字节, info=`gml-backup-v1`)。每个文件独立密钥，iv 另随机；因此不存在同密钥同 nonce。`GML_BACKUP_KEY` 是高熵随机串，不是口令，所以不用慢 KDF（手册要求 `openssl rand`）。
- 流式：64 KiB 分块读写，内存恒定。单消息上限约 64 GiB，超过则拒绝加密。标签放文件尾。
- 报告：`encrypted`、`encryption{algorithm,format_version,kdf,ms}`、`size`/`sha256` 为**密文**。不记录密钥或其派生物。
- 失败路径：加/解密先写 `<dest>.partial`（0600），认证通过后原子 rename；任何异常删除 partial。加密后立刻回读认证一遍，确认落盘密文能解开。
- 恢复演练：`.db.enc` 先按报告核对密文 sha256，再解密。探针读取用 0600 临时明文（演练结束删除）；落到目标目录时解密失败则回收本次创建的所有文件。密钥缺失/错误为 `DRILL_BACKUP_KEY_REQUIRED` / `DRILL_BACKUP_DECRYPT_FAILED`，退出码 1。

### 明文窗口（诚实边界）

`VACUUM INTO` 只能写文件，不能写流。因此有密钥时快照先落在备份目录内的 0600 临时文件（`umask 077`，文件名以 `.` 开头、`.plain.tmp` 结尾，不会被裁剪/恢复流程当成备份），校验与加密完成后用零覆盖并 unlink；校验失败或加密失败同样擦除（加密模式**不**把明文隔离成 `.failed`）。这不是"明文从不落盘"，而是"明文只在受限权限的临时文件里存活到加密完成"。限制：SSD 磨损均衡/写时复制文件系统上覆盖不保证物理擦除；`kill -9` 会遗留临时文件。缓解：备份目录放在加密卷；手册要求发现遗留 `.plain.tmp` 时清理。未采用的方案：内存数据库序列化（大库内存不可接受）、`backup()` 到管道（SQLite 无此接口）。

### 三库一致点

- 先对每个存在的库开写连接并 `BEGIN IMMEDIATE`（5 秒忙等超时，固定顺序避免死锁），全部持锁后，用只读连接依次 `VACUUM INTO`（VACUUM 不能在事务内，因此不在持锁连接上做），完成后全部 ROLLBACK 释放（没有任何写入）。校验、加密、裁剪都在窗口外做，窗口因此只含快照拷贝。
- 报告顶层 `consistency_stamp {id, frozen_at, released_at, freeze_ms, databases, note}`，每个库条目带同一 `id`。`note` 明写这是"短暂写冻结下的近似一致点"：窗口内无新提交，但这不是跨库事务，应用层若在窗口前后对两个库做了非原子的跨库操作，一致性仍取决于应用。
- 任一库拿不到锁：整次失败（`BACKUP_FREEZE_FAILED`），不产出文件，旧备份不裁剪。
- 影响：冻结期间其他写者最长等待一次快照拷贝的时间（含三库 VACUUM），大库需在低峰执行；`freeze_ms` 写入报告供容量评估。

## 后果与风险

- 大库加密耗时增加：报告记录 `encryption.ms`；`dmserver` 上的真实规模测量仍待做（本批未量）。
- 密钥丢失即备份不可恢复；密钥须与备份分离保管（手册 1.1）。
- 旧备份不会被轮换到新密钥；轮换采用"新密钥新备份、旧密钥保留至旧备份过期"。
- 备份报告本身不加密，不含秘密，但含路径与库结构统计（沿用 ADR-0009）。

## 验证

`tests/db-backup.test.mjs`：密文无 SQLite 魔数、无明文残留、sha256 为密文、往返完整性、共享 consistency_stamp、持锁失败干净退出、弱密钥退出码 2、加密模式校验失败不留明文、头/体/标签/截断/版本/错密钥篡改全部失败且不留文件。`tests/restore-drill.test.mjs`：加密备份端到端演练通过；错密钥/无密钥干净失败，目标目录无库文件。
