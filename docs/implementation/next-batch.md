## A. F06：后台会话撤销

### 已确认现状

- `server/middleware/auth.js:213–226` 签发 12 小时 JWT，没有服务端会话版本；`:248–291` 每次读取当前账号状态和权限，所以停用、降权会限制请求，但重新启用可能让旧 JWT 恢复可用。
- `server/routes/auth.js:166–210` 管理员重置、自助改密只更新哈希，未撤销旧会话；`:26–42` 登录失败区分不存在/停用/错密码，缺少限速。
- `src/store/auth.tsx:76–80` 退出只清本地状态；`src/api/client.ts:125–145` 下载的 401 处理与普通 JSON 路径不一致。
- `server/middleware/audit.js:86–125` 通用审计吞掉写入异常，不能直接用于“安全变更和审计原子提交”的保证。
- `server/mcp/tokens.js:124–139` 委托凭据是独立 F07 范围。后台 JWT 修复不等于 Agent Token 已撤销。

4. 非实现者静态复审并补负向用例，再由主执行器在 Linux 做焦点与三轮集成验证。

### 实现约束

- 为 users 增加单调递增整数 `auth_version`。JWT 签入版本，requireAuth 读取当前版本比较；无版本、错误类型、版本不匹配返回稳定 401（如 `SESSION_REVOKED`）。继续校验 audience、行业和当前权限，并限定预期算法。不得用“缺少版本等于零”兼容旧 JWT；升级后旧会话需要重新登录。
- 最小范围为账号全部会话撤销，不引入单设备/refresh token 承诺。自助改密、管理员重置、停用/启用、角色/超级管理员/组织/数据范围/客户归属变化，以及角色权限变化，应同步增加相关账号版本。普通姓名/电话更新不无条件踢人。
- 新建统一账号安全服务；字段变更、版本递增、严格安全审计在同一事务中。昂贵哈希可在事务外准备，但提交时校验旧版本/旧哈希，防止并发覆盖。审计失败必须回滚，日志不含密码、哈希、JWT 或完整请求体。
- 密码规则与 bootstrap 共用纯校验函数；新增、重置、改密保持一致，拒绝超过 bcrypt 72 UTF-8 字节上限。旧密码登录验证保留兼容，在实际改密时应用新规则。
- 登录校验类型和长度；不存在、停用、错密码统一 401 结构与提示，不存在账号也走预制 dummy bcrypt 比较，不能声称严格恒定时间。
- 节流至少覆盖来源地址和“行业+规范化账号”，规范化须与实际账号查询规则一致，不能未经迁移改变大小写等价语义。在昂贵校验前原子登记；需要 TTL、容量上限、并发拒绝、窗口恢复及可信代理策略。不得直接相信 X-Forwarded-For 或永久锁号。阈值应作为有测量依据的配置，不将草案数字当生产容量结论。若用内存，明确重启和多进程边界。
- 增加明确的 `POST /api/auth/logout-all`（auth Router 内相对路径 `/logout-all`）；UI 明示退出全部会话。网络失败可本地退出，但不能声称服务端撤销成功。改密后清状态，统一 JSON/下载/其他 fetch 的 401 处理，处理多标签页同步。
