# ADR-0001：生产、演示与测试数据隔离

状态：第一批实现；尚不构成生产上线验收。日期：2026-10-22。

## 问题与决定

上游 F04：普通启动会调用完整演示 boot，商品表为空时会重建业务表，随后补演示单据、配置和 Agent Token。真实企业的空商品库不能作为“允许重建”的依据。

采用显式 `GML_RUNTIME_MODE=production|demo|test`，缺省为 production。`NODE_ENV` 继续表示 Node 工具/依赖的运行环境，不作为允许演示灌数的依据。生产部署仍应设置 `NODE_ENV=production` 以启用依赖的生产行为。JWT 安全闸门按 `GML_RUNTIME_MODE` 或 `NODE_ENV` 任一为生产执行；漏写 NODE_ENV 不会允许公开/缺失密钥。

所有通过数据库连接层的访问都要求绝对路径 `GML_DATA_DIR`。初始化空数据库时以事务写入 `os_egp_runtime` 模式标记；已存在的非空无标记数据库拒绝打开，不自动采用、不推断用途。每次连接复用也检查模式，进程内改变数据目录会被拒绝。

生产启动动态加载独立 `production-boot.js`，仅执行原 schema/migrations 与 settings 初始化。演示 `boot.js`、`seed.js` 不进入生产启动的导入链；`bootIndustry`、`seedAll`、`resetDatabase` 对生产模式增加底层拒绝；所有公开卫星 `seed*` 与 `ensureDemoTokens` 同时校验模式及传入数据库的持久标记，防止绕过主入口。数据库标记在演示重置后保留，防止改变环境变量就把生产库当演示库重置。

## 精确边界

- 此标记是防误操作机制，不是对拥有文件写权限的恶意管理员的隔离。直接 SQLite 或手动篡改文件不在该防线内。
- 生产 schema 初始化仍保留上游迁移内的系统配置/字典，包括禁用且无 webhook 的通知样例配置。并未宣称迁移为纯 DDL。
- 测试已验证空生产库中的 users/products/sales_orders/purchase_orders/agent_tokens 为零；未逐表证明所有历史迁移无业务副作用。
- 原有自愈迁移可能重新应用配置。独立迁移、事务化版本升级及恢复演练在 M4 继续处理。
- 未实现管理员创建、旧库分类接管/迁移、生产功能开关与多租户隔离。因此生产模式目前是安全基础工作，不能作为可用生产产品交付。
- 不应通过手动插入模式标记跳过旧库保护。旧库接入需要另行设计备份、校验与显式迁移流程。
- 暂保留 `GML_*` 环境变量与数据库文件名，降低不必要的业务改动；这不表示新旧库可以共用。

## 验收与兼容影响

`npm run test:runtime` 验证缺省模式、路径要求、真实 HTTP 启动、重启保留数据、直接重置/灌数拒绝、切换模式拒绝、未知旧库/损坏库保护、测试灌数及标记保留。

`scripts/regress-isolated.mjs` 只在新建临时副本中显式指定 test，且把新增 tests 目录复制并纳入跑批。旧启动器/安装包脚本未迁移到新交付流程；它们缺少显式目录或模式时应报错，不能为了兼容而恢复隐式生产灌数。

回退应用代码之前必须核对数据版本与模式：原版 GML 不认识该保护标记，不能把受保护的生产数据交给原版演示启动器。没有经过演练的安全降级承诺。
