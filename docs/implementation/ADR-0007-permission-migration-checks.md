# ADR-0007：正常重启不得恢复已撤销的角色授权

日期：2026-10-22。关联 F04/F06；本条只解决正常 schema 完整情况下的两处错误自检触发，不能关闭整个迁移/恢复风险。

## 问题与决定

`026_mcp_guard.verify` 要求 MCP 确认权限的角色授予数量不少于默认值；`049_scm_role.verify` 要求供应链角色至少 20 项授权且不得有默认排除项。管理员通过角色管理合法削减权限后，下一次 `runMigrations` 会误判损坏、调用已有 `up()` 重新授予。

在隔离内存数据库上新增三项测试，改动前均实际失败：清空供应链授权后恢复了 56 项，清空 MCP 确认授权后恢复 6 项，自定义权限集合被添加默认项。没有使用真实业务数据库。

显式修正这两个旧迁移模块的 **verify 检查行为**：保留表、列、索引、权限字典、角色记录及已有定义指纹检查，移除对管理员当前授权集合的默认数量/排除项判断。`up()`、DDL、初次默认授权和已应用迁移记录不变；这不是悄悄重写已执行的数据转换。对正常完整数据库，管理员的授权选择不再触发重授。

## 验证与边界

`tests/migration-permission-policy.test.mjs` 检查首次默认授权、削减到零、连续重检、自定义集合保留以及两份迁移不出现在 healed 中。最终 Linux 结果以第二批验证记录为准。

其余迁移仍有“结构或定义指纹不一致时重跑 up”的旧机制。数据库结构损坏、定义变更、恢复旧备份或显式重建时，历史 up 仍可能修改系统配置/重新赋予默认权限。需要后续拆分 schema 修复与权限策略、版本校验和及受控恢复；本补丁不声称这些路径已安全。F04/F12 保持开放。
