# ADR-0002：未验收网络能力的生产门禁

日期：2026-10-22。状态：开发实现，尚非产品上线验收。

## 决定与理由

首版简易 ERP 聚焦人工采购、库存、销售及往来管理。商城身份验证、真实支付、外部连接器以及 Agent 委托权限尚未完成商业验收；不能因为接口能返回成功，就把它作为正式能力开放。

`server/capabilities.js` 是本批网络能力门禁的唯一名单。`production`（含缺省模式）在行业/凭据解析及业务路由之前拒绝以下路径及子路径，响应 HTTP 503，稳定业务码 `FEATURE_DISABLED`，不返回业务数据；明确 `demo`、`test` 保留原行为：

| 能力 | 生产禁用的路径 | 原因 |
|---|---|---|
| public_mall | `/api/mall` | 固定演示验证码、商城结算缺少真实支付闭环（F02/F10） |
| qimen_gateway | `/api/qimen` | 未认证库存读取与模拟写成功（F03） |
| oms_simulation | `/api/oms/sync`、`/api/oms/stock-push`、`/api/oms/qimen-message`、`/api/oms/qimen-stock-message`、`/api/oms/orders/:id/ship`、`/api/oms/orders/:id/refund` | 随机订单、模拟库存推送、无真实平台回传/资金确认的发货退款及演示报文不等于真实连接器 |
| im_connector | `/api/im/sync`、`/api/im/self-test` | 未验收同步及临时 mock transport 自检不应进入生产请求 |
| agent_access | `/mcp`、`/api/mcp` | 委托权限未完成治理；通用工具能直接调用领域服务，不能只禁 HTTP 商城/网关后仍开放 Agent 写入口 |

没有 `ENABLE_*` 环境变量绕过门禁。未来启用某项需要单独实现、测试、审查及发布决定。`/api` 返回 `capabilities` 显示当前运行时的 enabled 状态；demo/test 为 true 只表示可访问，不表示经过商用安全验收。

## 边界与保留行为

- 这是收缩首版产品范围，不是修复原商城认证、支付、奇门签名或 MCP 委托授权。F02/F03 等原问题的底层实现仍待后续替换；不能直接删除门禁宣称修好。
- 保留人工后台核心领域服务、OMS 非模拟业务路由、IM 只读状态以及后台鉴权。领域函数可由受信任服务器代码调用，本门禁不声称阻止本机代码执行者。
- 生产禁用整个 MCP 协议及管理入口，包括握手、读取、写入和凭据管理。只读 Agent 能力也需要另行验收后启用。
- 原 UI 导航、OpenAPI 静态接口全集及历史说明尚未全部缩减；实际可用性由 `/api` 的运行时 capabilities 及明确拒绝响应决定。前端隐藏未启用模块属于后续产品体验工作，不作为安全防线。
- CORS 预检可能由更早的 CORS 中间件返回 204；预检不执行业务处理，也不表示实际能力开放。实际业务请求仍由门禁拒绝。
- 返回 503 表示本版本未启用，不提供自动重试/自动放行或“模拟成功”回退。

## 验证范围

专项命令：`node --test tests/capabilities.test.mjs`（Node 22）。

测试覆盖缺省生产及显式运行模式的策略、无关开关不能覆盖禁用；真实服务上的商城登录/下单路径、奇门查询、OMS 模拟、IM 同步、自检、MCP 握手/通用写工具/管理入口拒绝；大小写和尾随斜杠、不同 HTTP 方法；拒绝前后客户、OMS、Agent、IM 运行记录计数不变；基础 API、健康检查、采购鉴权保持；demo 与 test 的商城登录、奇门错误响应、MCP 握手仍可用。

本批使用 Mac mini 上的 Node 本地开发验证，每次全新临时数据库、loopback 随机端口，无真实外部连接或支付。它不等于 Linux 目标服务器部署验收；Linux/Python 验证交由父任务指定服务器。未执行 UI 端到端或真实连接器测试。

2026-10-22 Mac mini 开发验证结果：专项 4/4 测试通过（31.2 秒，无跳过）；`git diff --check` 通过。`check-contract-routes.mjs` 退出 0：契约指向不存在路由为 0；反向仍有 71 条历史未登记路由，其默认检查不计失败，未宣称完整契约一致。

## 独立复审补充

生产门禁补上 OMS `/stock-push`：原接口没有外部传输却记录 `success` 和 `last_sync_at`。枚举同类路径后，同时禁用 OMS 的平台发货回传与退款端点：前者可随机生成快递信息并记录回传成功，后者没有真实资金确认却推进平台退款并记录同步成功。核心 `/api/sales` 发货和 `/api/refunds` 人工业务未改变。UI 旧入口可能仍可见但操作明确返回 `FEATURE_DISABLED`；后续按 capabilities 隐藏，不能以隐藏 UI 代替后端门禁。

补充测试使用生产空库中手工建立的合成管理员、平台和订单，先证明凭据可以读 OMS 平台，再发起库存推送、发货及退款请求（含大小写/尾随斜杠）。拒绝前后平台同步时间、订单全部字段、OMS日志、审计及库存流水均保持不变；不使用演示 seed 初始化生产库。

补充验证：5/5 专项测试通过（33.9 秒，无跳过）。反例验证暂移除 stock-push 门禁后，管理员测试明确得到 200 而非 503 并退出 1；随后已恢复源码。最初新增测试因表名拼写错误报 SQLITE_ERROR，改为实际 inventory_transactions 后完整重跑通过。
