# GML 开发策略 v1：开源复用优先

> 日期：2026-10-15 ｜ 来源：用户指令 —— "开发过程中，多可以去 github 上去找人家已经开源成熟的系统下载下来，改一改就好了。"
> 性质：**贯穿全项目的开发策略**，适用模块 03~26
> 脱敏：全文不含任何真实客户名与品牌名

---

## 一、策略原则

1. **能抄就抄、能 fork 就 fork，不从零写。**
2. 但**不盲目搬运** —— 按「技术栈匹配度 × 许可 × 可改造性」筛选。
3. **抄骨不抄皮**：抄功能清单、抄表结构、抄流程设计；代码在与我们的架构对齐后落进自己的库。

---

## 二、三条硬约束（决定了很多项目只能"抄设计"不能"抄代码"）

| # | 约束 | 说明 |
|---|---|---|
| 1 | **技术栈** | 我们是 **React + Vite + Tailwind + Express + better-sqlite3**（Node 全栈 + 单文件库）。PHP / Java / Python 系项目**只能抄设计** |
| 2 | **MCP 原生**（第 0 条口径） | 能力从第一天即以标准 MCP 暴露 —— **没有任何开源项目具备**，这一层必须自建 |
| 3 | **脱敏 + 双行业** | 品牌名不得进代码；美妆/餐饮双版本、双套部署 |

## 四、候选评估（下一步动作）

1. 逐个 clone 到 **`~/工作文档/gml/_ref/<project>/`**（**不进主仓**，已由 `.gitignore` 排除）
2. 记录：star 数、最近提交时间、License、技术栈、可借鉴点
3. 产出《GML 开源复用评估表》，标注每个项目「抄设计 / 借组件 / 可用代码」的结论

---

## 五、许可红线（必须遵守）

| 许可 | 处理 |
|---|---|
| **MIT / Apache-2.0** | 可商用、可修改；**保留版权声明** |
| **GPL / AGPL** | **传染性**；参考设计不受限，但**复制代码需先评估** |
| **未声明许可** | **不得使用** |
| 任何引用的代码 | **必须剥离其中的人名、公司名、品牌名**（与脱敏铁律一致） |

---

## 六、存放约定

```
~/工作文档/gml/
├── _ref/                 # 参考仓库（只读，.gitignore 排除，不进主仓）
│   ├── idurar-erp-crm/
│   ├── bagisto-b2b/
│   └── warehouse-wms/
├── server/               # 我们的后端（借鉴后重写）
└── src/                  # 我们的前端
```

**纪律**：`_ref/` 只读参考，任何代码**不得直接从 `_ref/` 复制进 `server/`、`src/` 而不做适配审查**；尤其是代码注释里的作者名、仓库地址、示例公司名要清干净。
