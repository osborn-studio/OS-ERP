## 3. `check:dict` 从"手工跑"接进常驻回归

### 3.1 为什么必须接

`scripts/check-inv-txn-dict.mjs` 在本批之前**只被人手跑过** —— 证据里能看到
`GML_DATA_DIR=/tmp/w-disp-db npm run check:dict`（见 `docs/evidence/批次QC-DISP_…/回归与契约计数.txt`）。
而"**判据存在 ≠ 判据被执行**"是本项目用一条真缺陷换来的铁律（缺陷 186：`assertPositiveQty` 一直在，
但调用点在"可能一次都不进"的循环里 ⇒ 判据从未执行）。**没人跑的守卫就是装饰。**
它当天上线就捞出过真 bug（拆卸单 `DS` 与经销商对账单 `DS` 前缀撞车），这种"只在有人想起来时才发现"
的形态不可接受。

### 3.2 怎么接

`scripts/regress-all.mjs` 新增一条 `check:dict`，跑在**模块初始化期取的库快照**上：

- 落点 `os.tmpdir()/gml-dict-snapshot-<pid>`（可用 `GML_DICT_SNAPSHOT` 覆盖），**跑完即删**；
- 快照**取自本轮实际在跑的那批库**（`process.env.GML_DATA_DIR || <repo>/data`）——
  否则会出现"测试在 A 库跑、守卫在 B 库判"，两条判据看起来都在、实际互不相关；
- 快照取在**任何 `test-*.mjs` 落笔之前**（模块初始化期），所以它反映本轮起点的库状态；
- 备不出快照 ⇒ 该条**照旧进清单并红**，不是从清单里消失 —— "少判一条就报"。
