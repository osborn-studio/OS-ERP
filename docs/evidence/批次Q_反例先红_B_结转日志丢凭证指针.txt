# 批次 Q 反例先红后证 · 反例 B：结转写了日志，但日志里没有凭证指针

## 注入内容

文件 server/lib/closing.js → carryForward()

    -  voucherId: v.id,
    +  voucherId: null, /* 反例注入 B：结转日志不记凭证指针 */

含义：日志写下来了，理由也对，金额也对 —— **只有凭证指针丢了**。
这是"日志看起来有、实际认不出是哪张票"的形态：如果只看"有没有日志"，它是全绿的。

## 预期

两条覆盖**不同失效方式**的探针同时响：
  · PERIOD_AUDIT_DESYNC     —— 重放得到"未结转"，而期间表上是"已结转"（看状态对不对）
  · PERIOD_AUDIT_VOUCHER_ORPHAN —— 账上那张结转凭证没有任何日志认领（看票有没有主）

## 实际输出（注入状态下）


（共 5 处红，随后因关账被自证拦下而中断 —— 主干闸门塌了，下游全塌，与批次 M/N 同一形态。）

## 顺带做的一处加固

第一次跑时探针断言排在 `closePeriod` **之后**，而关账会先被自证拦住并抛错 ⇒
"这张票没人认领"这条证据只能从异常栈里读。
已把它**提到结转之后、关账之前**：反例注入时最要紧的证据必须最先跑出来。
