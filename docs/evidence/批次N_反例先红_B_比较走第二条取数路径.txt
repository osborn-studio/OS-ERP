    -  const base = computeReport(db, { reportCode, period: basePeriod })
    +  const base = computeReport(db, { reportCode, period: shiftPeriod(basePeriod, -1) })

含义：基期列不再来自"模式推导出的那个基期"，而来自上上期。
这是"比较另写一条取数路径"的最小形态 —— 两列都长得像真的，谁也不报错。

## 第一次跑：一声不吭（52 项全绿）→ 暴露一个真实弱点

原因：`base_period` 这个字段取自**模式推导**，而基期列取自**实际计算**，两者可以分离。
于是"算的是 2026-08、自称的是 2026-09"这件事没有任何人发现；
再叠加 2026-08 与 2026-09 的余额恰好相同（两期都无发生额），金额类的探针也测不出来。

修正：`compareReport` 的 `base_period` 改为取**实际算出来的那一期**（`base.period`）——
让"结果自称的期间"与"真的算了哪一期"绑定，不一致就由 COMPARE_BASE_PERIOD_BAD 报出来。

### 补充：为什么 COMPARE_BASE_MISMATCH 没有一起响

因为 2026-08 与 2026-09 的余额**恰好相同**（两期都没有发生额），
所以"金额类"探针在这组数据上本来就是哑的 —— 这恰好证明两条探针**覆盖不同的失效方式**：
`COMPARE_BASE_PERIOD_BAD` 看"期间对不对"，`COMPARE_BASE_MISMATCH` 看"金额对不对"。
只留一条就会留下一个洞。
