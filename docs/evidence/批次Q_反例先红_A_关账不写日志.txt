# 批次 Q 反例先红后证 · 反例 A：关账改了状态却不写审计日志

## 注入内容

文件 server/lib/report.js → closePeriod()

    -  logPeriodChange(db, { period: p, action: 'period_close', statusBefore, statusAfter: 'closed', remark, actor })
    +  /* 反例注入 A：关账不写审计日志 */

含义：期间表被改成 closed，但日志里没有这一笔。
这是本批要防的那一类缺陷的最小形态 —— 界面上「已关账」显示得好好的，
`closed_by` / `closed_at` 也都在（它们本来就在期间表上），
**只有把日志重放一遍才会发现"这一期不可能变成已关账"**。

## 顺带暴露的一个测试自身问题（已修）

第一次跑时测试**崩在 Q4 的 `l1.action`**（`l1` 是 undefined）——
日志缺失时 `.action` 直接抛异常，于是 **DESYNC 探针根本没跑到**，证据没取到。

已修两处，并把探针断言**提到最前面**：
  · `.pop()` / 末位取值一律 `|| {}`；
  · `Q.auditPeriodTrail` / `R.auditReport` 的断言紧跟三次动作，不再排在细节断言之后。
**教训：反例注入时，测试必须给出"可读的红"，而不是崩在无关的位置 ——
崩在无关位置等于把最重要的证据丢掉了。**
