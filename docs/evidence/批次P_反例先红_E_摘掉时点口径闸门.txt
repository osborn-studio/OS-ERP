## 这道闸门为什么必须存在（注入后实测的后果）

闸门摘掉之后，程序**不报错、不崩、也不缺数** —— 它安静地产出一张这样的表：

```
   1 货币资金        本期 261109.05   累计 0
   2 应收账款        本期 312702.40   累计 0
   ...
   9 资产总计        本期 2441214.05  累计 0
  15 负债合计        本期 622108.15   累计 0
  21 所有者权益合计  本期 1819105.90  累计 0
  22 负债和所有者权益总计 本期 2441214.05 累计 0
资产 2441214.05 负债 622108.15 权益 1819105.90
资产 = 负债 + 权益 ? true
```

**整个"本年累计"列全是 0，而三张恒等式一条都没破。**
机械原因：区间取数对象（`subjectRangeMovements`）里**没有** `closing_signed` 这个字段
（它是 `null`，因为区间只有发生额、没有余额），求和时 `null` 被当 0 加了起来。
换句话说，"时点报表做累计"这件事不是"算得不对"，而是**根本没有东西可算**——
所以它不会产生任何"看起来不对"的信号，只会产生一列整齐的 0。
一列整齐的 0 最容易被读成"今年还没开始记账"。

**结论：这件事必须由闸门拦死（409 + 一句人话），不能靠探针 ——
因为没有任何探针能区分"全 0 是因为算错了"与"全 0 是因为真的没有"。**
