# 伴圆AI原生ERP 本地安装手册

适用版本：2026年10月21日本地源码交付版。面向接收安装包的演示人员、实施顾问和维护人员。按本手册可以在自己的电脑上安装、启动、备份和恢复演示环境。

本包是演示及方案验证环境，不是已完成生产上线认证的企业系统。首次启动生成虚构数据，默认只允许本机访问；美妆连锁、连锁餐饮为本次业务验收范围，服装不在范围内。

## 一 安装前准备

| 项目 | 要求 |
|---|---|
| 运行环境 | Node.js 22.x LTS，安装时保留 npm；不使用 Node 18、20、24 或其他主版本 |
| 浏览器 | 能运行现代 JavaScript 的浏览器，例如 Chrome、Edge、Safari |
| 网络 | 首次安装需访问 npm 官方仓库及原生模块下载站点；不能保证断网首次安装 |
| 本地空间 | 建议预留至少 2GB，安装目录须可读写 |
| 数据库 | 无须单独安装数据库，SQLite 文件存放在本副本 data 目录 |
| 已验证平台 | 本次安装验证以 macOS Apple Silicon 为准；Windows、Linux 提供脚本和步骤，未做对应实机验收 |

从 Node.js 官方网站获取 22.x 安装程序。安装完重新打开终端，运行以下命令，第一行须是 v22 开头，第二行须返回 npm 版本号。

```bash
node -v
npm -v
```

不要把原机的 node_modules 复制到其他系统。better-sqlite3 包含原生模块，不同系统、CPU 和 Node 主版本不通用。首次安装会按当前电脑下载或编译对应版本。

## 二 解压及目录检查

完整解压 ZIP 到普通本地目录，不要在压缩包预览窗口中直接执行。避免同步盘、只读目录、系统保护目录和过长路径；目录名允许中文及空格。

| 目录或文件 | 用途 |
|---|---|
| src | React 前端完整源码 |
| server | API、业务服务、数据库结构和迁移、种子数据、MCP 服务 |
| scripts | 安装维护、代码检查、回归测试和重新打包脚本 |
| reusable | 可复用模块及相关说明 |
| public 和 dist | 静态资源及已构建前端；接收者不必先编译 |
| docs/本地交付 | 安装、操作、演示、开发及安全说明原文和验收记录 |
| 手册 | 可离线打开的 HTML 手册，双击 install.html 即可 |
| MANIFEST.json | 发布文件的 SHA256 清单 |
| package-lock.json | 锁定依赖版本，安装使用 npm ci |

包中不包含原机业务数据库、实际密钥、环境配置、录屏、日志、Git 历史或 node_modules。首次启动才会在此副本生成 data 目录内的样本库。

## 三 macOS 安装启动

1. 双击 install.command。首次联网安装运行依赖，出现 Ready 表示安装完成。
2. 双击 start.command。等待首次建库完成，健康检查通过后自动打开登录页。
3. 默认访问 http://127.0.0.1:3001/login，选择美妆连锁或连锁餐饮，再选择角色登录。
4. 保持启动终端窗口开启。停止时在该窗口按 Ctrl+C；日后再双击 start.command，已有业务数据会保留。

如果系统拦截脚本，请先确认来源及校验结果，再按系统提示允许打开。也可在终端进入解压目录后运行：

```bash
node scripts/local-manage.mjs setup
node scripts/local-manage.mjs start
```

只有提示没有执行权限时，才对本包脚本添加权限，不要全盘关闭系统安全保护：

```bash
chmod +x install.command start.command backup.command
```

## 四 Windows 安装启动

1. 安装 Node.js 22.x，确保加入 PATH，重新打开命令窗口。
2. 用资源管理器完整解压，再双击 install-windows.bat。
3. 安装成功后双击 start-windows.bat。浏览器打开登录页后保持黑色运行窗口开启。
4. 在该窗口按 Ctrl+C 停止服务。如提示终止批处理，确认即可。

也可在 PowerShell 或命令提示符进入解压目录后，执行与 macOS 相同的两条 node 命令。

此路径尚未在 Windows 实机执行；遇到编译工具错误，应先检查 Node 是否确为 22.x 及下载站点是否可达。必须源码编译时，由 IT 配置 Python、Visual Studio C++ 构建工具，再重试安装，不要关闭 TLS 校验。

## 五 Linux 安装启动

安装 Node.js 22.x 和 npm 后，在解压目录运行：

```bash
node scripts/local-manage.mjs setup
node scripts/local-manage.mjs start --no-browser
```

在同一台电脑浏览器打开默认登录地址。无桌面环境时不会自动出现网页。若原生依赖需要编译，须预装 Python 3、make 和 C++ 编译工具。Linux 路径未在本次环境实机验收。

Dockerfile 和 docker-compose.yml 随源码提供，属于 IT 可选部署路径，不是本次已验收的双击安装方式。使用前须自行配置 GML_JWT_SECRET、检查端口暴露范围及卷备份；不要直接以默认账号向公网提供访问。

| 角色 | 账号 | 初始密码 | 场景 |
|---|---|---|---|
| 管理员 | admin | 12345 | 总部功能及系统设置 |
| 供应链主管 | scm | 123456 | 采购、库存、生产、质量 |
| 财务 | finance | 123456 | 应收、凭证、报表 |
| 门店店长 | store01 | 123456 | 本店 POS、库存和要货 |
| 经销商 | dealer01 | 123456 | 美妆版本人订货、对账 |
| 老板 | boss | 123456 | 经营查询及授权审批 |
| 只读访客 | viewer | 123456 | 授权范围内只读访问 |

其他演示账号：purchase、sales、warehouse，初始密码均为 123456。餐饮演示不要使用经销商角色。

登录后检查经营看板、销售订单、库存和手册能否打开；退出后分别用 store01、dealer01 验证角色差异。后台、POS、商城入口分别为 /login、/pos、/mall。

```bash
node scripts/local-manage.mjs doctor
node scripts/verify-release.mjs
```

doctor 输出 Node、SQLite、前端及健康检查情况，不输出签名密钥。服务未启动时 health 显示 not running 属正常；安装必需项失败时退出码非零。verify-release 应显示 0 errors。

## 七 端口和配置

安装工具首次创建 .local/config.json，内容为端口和本机随机签名密钥。不要把这个文件发送给他人；每次启动保留它，避免旧登录令牌因密钥变化失效。

默认端口 3001，默认只监听 127.0.0.1。端口已占用时启动工具会退出，不会结束占用进程。可编辑 config.json 的 port 字段为 3011，或使用临时环境变量：

```bash
# macOS / Linux
GML_LOCAL_PORT=3011 node scripts/local-manage.mjs start
```

```powershell
# Windows PowerShell
$env:GML_LOCAL_PORT="3011"
node scripts/local-manage.mjs start
```

更换端口后，登录、POS、商城和 MCP 端点中的端口均应同步更改。离线手册的“返回系统”链接默认仍指向 3001；此时手动输入实际地址。

本地工具强制使用本副本 data 目录，不继承外部 GML_DATA_DIR、GML_DB 或旧 JWT_SECRET。开发者如需自定义存储或局域网访问，应走开发部署路径并自行做安全评估。

## 八 备份和恢复

备份建议先停止服务，再双击 backup.command 或 backup-windows.bat，也可执行：

```bash
node scripts/local-manage.mjs backup
```

备份保存在 backups 下的时间戳目录。SQLite 通过 backup API 导出，避免直接复制运行中 DB 丢失 WAL 内容；配置文件一并备份。多行业同一业务时点的一致性要求先停服务。备份含数据库和签名密钥，须按敏感文件管理。

恢复步骤：

1. 停止所有指向此安装副本的服务，先备份当前 data 和 .local。
2. 将当前 data 目录改名保留，创建新的空 data 目录。
3. 将指定备份中的 gml_cosmetic.db、gml_food.db、gml_apparel.db 放入新的 data；不要混入旧的 -wal、-shm 文件。
4. 将同次备份的 config.json 恢复到 .local/config.json。
5. 启动并检查行业、近期单据、库存和角色；核对后再处理旧目录。

不要混用不同日期的数据库和配置。不要在服务运行中覆盖 DB。首次安装不依赖备份，直接启动即可生成新样本。

## 九 重置演示及升级

日常退出、重启和重复安装不会主动清空已有业务数据。需要恢复演示初始态时，先停止服务并备份，再将 data 目录改名为 data-before-reset，重新启动。系统将在新的 data 中生成全新样本，原目录保留可回退。

不要在演示中误点 npm run reseed、reset 或测试脚本：其中有重建或修改数据库的工具。只在独立测试副本执行开发命令。

升级时先备份，在新目录解压新版并安装依赖，将停机备份恢复到新版，验证后再切换使用。不要覆盖旧版后才发现无法回退；跨版本兼容性须单独验证。

## 十 常见故障

| 现象 | 检查及处理 |
|---|---|
| node 或 npm 找不到 | 安装 22.x，重新开终端；检查 PATH |
| npm 下载失败 | 检查官方 npm 仓库及原生模块站点网络；保留原始错误，不要使用关闭证书校验的做法 |
| NODE_MODULE_VERSION 或 invalid ELF 错误 | 不同系统或 Node 版本的依赖混用；切到 Node 22，再运行 setup 重新安装 |
| Port unavailable | 更换本包端口，不要随意结束其他服务 |
| 网页未打开 | 看启动窗口是否出现 ready，手动输入显示的登录地址 |
| 首次建库较慢 | 等待日志完成；健康检查最多等待 180 秒，超时会停止本次子服务 |
| 登录成功但无权限 | 先核对所选行业和角色；门店、经销商不可进入总部页面 |
| 校验报告 hash mismatch | 文件被改动或解压不完整；开发改动先保留，普通接收者应重新完整解压 |
| 备份没有数据库 | 至少完成一次首次启动；确认操作的是正确安装目录 |

## 十一 正式使用前的边界

默认密码、商城固定验证码、模拟付款及外部平台演示适配不能用于公网生产。正式使用须完成账号治理、HTTPS、访问控制、最小权限、审计、备份恢复、容量和并发测试，并核验真实业务规则。

包中没有附带国外大模型账号、API Key 或额度。MCP 是 ERP 能力接口，不等于已经接通某个大模型。模型供应商、联网策略、成本及数据出境等须按客户要求另行评估和配置。
