# 伴圆ERP 版本记录与交付规范

林师傅确认的交付要求：每次完成代码更新后，同步GitHub，并将完整安装源码包与各类文档打成一个总包交付，保留版本更新记录。

## 固定交付流程

1. 完成代码与配套文档修改，更新package.json及锁文件版本。功能更新递增次版本，兼容修复递增补丁版本；不以日期替代产品版本。
2. 在隔离环境执行与改动风险匹配的测试、类型检查、构建和依赖审计；有失败或未测试范围时明确记录。
3. 提交本次相关代码、文档和版本记录，同步GitHub main，核对远程提交SHA；不得强推或误提交其他人的改动。
4. 从对应提交生成安装源码包，内含预构建前端、完整前后端源码、安装启动脚本、手册及逐文件SHA256清单。首次联网安装需Node.js 22.x及npm，不宣称通用离线首装。
5. 对本次实际交付的ZIP重新解压执行安装验收，不用旧包的测试代替新包验收，不触碰正在使用的数据库。
6. 生成一个“完整交付总包”：安装源码ZIP、安装/操作/演示/开发与MCP/安全等全部现有手册、可编辑原文、版本记录及去敏后的验收结果。总包外另附SHA256。
7. 创建对应GitHub Release，将总包及校验文件上传，记录版本、提交、测试结果、依赖风险及未验证范围。核对下载资产摘要与本地一致。
8. 向林师傅提供本地总包链接、GitHub Release链接和简短更新说明。保留历史包，清楚标注最新版本，不静默覆盖旧版。

若权限或网络导致同步失败，保留本地成果并明确报告，不把“本地已提交”说成“GitHub已同步”。交付包不得包含原机数据库、真实客户资料、.env、密钥、令牌或含敏感信息的原始日志。
