## 四、本期重点

### 4.1 批次 G · 渠道协议价与返利核销（`031`）
协议价档案（客户 × 品类 × 周期）取价接入；返利**计提 → 试算 → 核销 → 冲应收**闭环。

### 4.2 批次 H · 业财一体凭证（`032`）
科目表 + 凭证模板 + 凭证生成与试算平衡。**采购入库 / 销售出库 / 收付款各生成平衡凭证**。
验收反例做了「先红后绿」：把平衡校验与叶子科目校验摘除后 `verify-seed` 变红。

### 4.3 收尾批次（第 13 批）—— 三条遗留不变量 + 一类 seed 缺陷
- `A10` 部分发票红冲误作废**共享**整笔应收 → 按票与债权的关系分流处理；
- `A17b` 改单只改单头不重算 / 负数量出入库反向 / MCP 只验必填 → 值域闸门 + 重算条件修正 + 入参校验扩展；
- `A18` 采购付款核销不校验主体·状态·金额符号·未付余额 → 四道闸 + 两个时点各重验一次。

**集成重建时暴露一类 seed 缺陷**（"挑样本"的筛选各写一份，两处漏了排除原料/包材），导致整库重建崩溃；
顺带抓到**重建不可复现**（排序不确定 + 留痕表漏登记清理清单）。
新增两道防线：`KEEP_TABLES` 清单完整性守卫（`verify-seed` §16）+ `verify-reseed.mjs`（两次重建逐项比对，已接入回归）。

### 4.4 批次 J · 退款单流程（`033`，范围裁剪项第 1 项）
此前销售退货只把"待退款额"**登记**在退货单上，没有任何单据或账务后果与之对应 ——
说得出"该退多少"，答不出"退没退"。
本批落最小闭环：退款单（草稿 → 已退款 → 已作废）+ 分摊明细 + 退款上限判据 + 幂等键 + 账务后果（凭证模板）。
**退款上限 = 退货单待退款额 − 已退金额**，超退整笔不落库。
