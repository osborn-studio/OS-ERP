`ENTERPRISE-LICENSE.md` 列出的企业版路径包括（节选）：

- `packages/modules/rbac/`
- `packages/core/core-flows/src/rbac/`

- `packages/core/framework/src/policies/`

**判定与硬约束**：

- ✅ `packages/modules/promotion`（促销引擎）**不在**企业版清单 → 可安全参考（MIT）。
- 🚫 **GML 模块 05（组织与权限、行级数据规则）一律不得参考 medusa 的 rbac / policies / check-permissions / field-filter 相关路径** —— 那些是需要商业授权的企业版材料。权限部分**只能参考 casbin（Apache-2.0）**。

## 附录：主仓自身依赖漏洞复核（2026-10-15 16:25 补）

`git push` 时 GitHub 提示「默认分支 8 个漏洞（2 high, 6 moderate）」，来源为 Dependabot 扫描 `package-lock.json`。已逐条核实实装版本，结论如下。

### 结论先行

**8 条全部被 GitHub 标记为 `development` 作用域，但其中 1 条真实影响生产**：前端运行时库被误放在 `devDependencies`，漏洞因此被标成 dev，而它们的代码会打进生产 bundle。

### 一、逐条核实（实装版本 ≠ 声明版本，必须看实装）

| 包 | 告警严重性 | 漏洞范围 | **实装版本** | 是否命中 | 真实影响 |
|---|---|---|---|---|---|
| `react-router` / `react-router-dom` | MEDIUM ×2 | `< 7.18.0` | **6.30.6** | ⚠️ **命中** | **影响生产**：开放重定向（CVE-2026-53669）与反序列化构造函数注入（CVE-2026-53666），前端 `App.tsx`/`Layout.tsx`/`Login.tsx` 等正在使用 |
| `braces` | HIGH | `<= 3.0.3` | 3.0.3 | 命中 | 构建期 DoS，生产无影响 |
| `esbuild` | MEDIUM | `<= 0.24.2` | 0.21.5 | 命中 | 仅 dev server 可被跨站请求，生产无影响 |
| `postcss-selector-parser` | MEDIUM | `< 7.1.6` | 6.1.4 | 命中 | 构建期解析复杂度，生产无影响 |
| `vite` | HIGH | `>= 8.0.0, <= 8.0.15` | **5.4.21** | ✅ **不适用** | 范围不匹配，属误报 |
| `vite` | MEDIUM | `>= 8.0.0, <= 8.0.4` | **5.4.21** | ✅ **不适用** | 范围不匹配，属误报 |
| `vite`（launch-editor） | MEDIUM | `<= 2.14.0` | — | 待核 | 仅 Windows UNC 路径场景 |

### 二、关键发现：前端运行时库被归到 `devDependencies`

`package.json` 第 30-44 行的 `devDependencies` 里包含：

```
react ^18.3.1 / react-dom ^18.3.1 / react-router-dom ^6.28.0
recharts ^2.13.3 / lucide-react ^0.460.0
```

**两个后果**：

1. **漏洞定级失真**：这些库的代码会被 Vite 打进生产 bundle，但 npm/Dependabot 按声明位置把它们算作 dev —— 于是 `react-router` 的两条生产级漏洞被显示成「development 告警」，容易被误判为"不用管"。
2. **生产构建会失败**：一旦部署环境执行 `npm ci --omit=dev`（或 `NODE_ENV=production` 下安装），这些库都不会被安装，**前端根本构建不出来**。

### 三、建议动作（**未擅自执行**，等主编写确认）

1. **把 `react`、`react-dom`、`react-router-dom`、`recharts`、`lucide-react` 从 `devDependencies` 移到 `dependencies`** —— 这是分类修正，不改版本，风险低，建议优先做。
2. **`react-router-dom` 升到 `7.18.0+`** —— 唯一影响生产的一条。注意 v6→v7 属**破坏性升级**，路由 API 有变化，需回归 `App.tsx` 与所有 `useNavigate` / `<Link>` 调用点，建议单独一轮做并跑完整前端冒烟。
3. 构建期依赖（`braces` / `esbuild` / `postcss-selector-parser`）可用 `npm audit fix` 或直接升版本，非破坏性，可随日常维护处理。
4. `vite` 两条为误报（实装 5.4.21，不在 `>=8.0.0` 范围），无需处理。
